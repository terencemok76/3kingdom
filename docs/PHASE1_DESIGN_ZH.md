## 1. 概覽
- 工作名稱：`3Kingdom`
- 目標平台：Godot 4.6.2 + C# 的 2D 桌面策略遊戲。
- 靈感來源：早期《三國志》式戰略流程，但 Phase 1 採簡化範圍。
- 核心循環：以月份為單位進行城市管理、武將指令、AI 勢力行動與擴張。

## 1.1 劇本 / 故事
- 目前劇本只有一個：
- `storyId`：`yellow_turban_rebellion`
- 英文名稱：`Yellow Turban Rebellion`
- 中文名稱：`黃巾之亂`
- 開始日期：`184 年 1 月`
- 每個劇本檔應自行持有：

## 2. Phase 1 目標
- 交付一個可玩的 vertical slice。
- 2D 地圖包含可連線城市。
- 月份推進與回合流程可運作。
- 城市與武將有基本資料模擬。
- 玩家可執行核心指令。
- AI 勢力可自動行動。
- 基本勝敗條件可完成一局遊戲。

- 音效、動畫與美術 polish。

## 3.1 Phase 1.5：內政與官職擴充
- Phase 1 的 `Develop` 將演化為更完整的 `Internal Affairs` / `內政` 系統。
- 內政是一個可多月持續的武將派任系統。
- 每個內政工作需要一名武將。
- 同一名武將同時只能執行一種內政工作。
- 玩家可在 UI 中中止內政排程。
- 戰爭或事件日後可中斷排程。

### 內政工作
- `Farm`：農業。
- `Commercial`：商業。
- `Defend`：防衛。
- `WaterControl`：防災。主要提升城市 `防災`，並少量提升 `忠誠`。
- `Construction`：建設。

## 3.2 Phase 1.5：道具系統
- 加入武將裝備與特殊道具。
- 道具會影響武將屬性，進而影響內政、城市與戰鬥結果。
- Phase 1.5 的道具系統只屬於戰略層，不加入獨立戰鬥場景裝備 UI。
- 目前實作補充：
- `WorldState.Items` 已作為全域道具資料來源。
- 搜索 / 訪察民情取得的道具會先進入 `勢力庫存`。
- `賞賜` 會從 `勢力庫存` 指派道具給武將。
- `索回道具` 會把武將持有道具收回 `勢力庫存`。
- `查看 -> 勢力道具` 可直接檢視勢力庫存、持有人、類型、稀有度與能力加成。

## 3.3 Phase 1.5：外交基線版
- 新增 `外交` 指令分類，屬於戰略層、城市發動、勢力對勢力的互動。
- 目前已實作的外交行動：
- `同盟`
- `休戰`
- `贈禮`
- AI 對玩家勢力的 `同盟 / 休戰 / 贈禮 / 索貢` 已改為 `提案制`，不再直接自動生效。
- 外交需從當前城市指派一位使者武將，並在月底結算。
- `同盟 / 休戰` 會建立或刷新勢力關係資料。
- `贈禮` 目前可送出 `金 / 糧 / 馬`，並依總價值提高關係值。
- `索貢` 目前可要求 `金 / 糧 / 馬`，成功時會依資源項目分別從目標勢力最富 / 最多糧 / 最多馬的城市扣除，再轉入發動城市。
- 目前外交狀態會記錄於 `DiplomacyRelationData`，並可由 `查看 -> 外交關係` 查看。

## 4. 核心遊戲模型
### 4.1 時間系統
- 時間單位：每回合 1 個月。
- 每月流程：
1. 玩家階段：對己方城市下達指令。
2. AI 勢力階段：各 AI 勢力依序行動。
3. 月底結算：
- 結算排程中的 `Develop` / `Internal Affairs`。
- 結算排程中的 `Recruit`。
- `Search` 功能已遷移至 `民事 > 訪察民情`，不再作為獨立玩家按鈕。
- 結算排程中的 `Move`。
- 結算排程中的 `Attack` 並進入戰鬥判定。
- 套用兵糧維持費與忠誠 / 民心壓力。
- 推進月份。
- 季節收入：
- `Gold` 在每年 4 月一次收取全年累積。
- `Food` 在每年 8 月一次收取全年累積。
- 全年累積使用城市目前月收入公式乘以 `12`。

### 4.2 勢力與城市
- 世界包含多個勢力與中立城市。
- 城市有：
- 擁有勢力。
- 資源。
- 武將列表。
- 連接城市列表。
- 地圖座標。
- 城市只可被一個勢力持有。
- 中立城市 `OwnerFactionId = 0`。
- 玩家起始城市會在遊戲開始後自動選中。

### 4.3 武將
- 武將資料來源：`data/person/officer.json`。
- 武將以 `Id` 作為唯一識別。
- 顯示名稱支援英文與繁中。
- 年齡由 `currentYear - birth_year` 計算。
- `death_year` 暫作歷史參考，不在 Phase 1 強制死亡。
- 未滿 18 歲的武將：
- 不會在劇本起始加入勢力。
- 不會被搜尋出仕。
- 不可被登用。
- 武將基本屬性：
- `Strength`：武力。
- `Intelligence`：智力。
- `Charm`：魅力。
- `Leadership`：統率。
- `Politics`：政治。
- `Combat`：戰鬥。
- `Loyalty`：忠誠。
- `Ambition`：野心。
- 武將狀態：
- `Idle`：待命。
- `Develop` / `Internal Affairs`。
- `Recruit`。
- `Move`。
- `Attack`。
- `Civil Investigation` / `訪察民情`。

### 4.5 兵種
- Phase 1.5 基本兵種：
- 步兵 / `Infantry`
- 槍兵 / `Spearman`
- 騎兵 / `Cavalry`
- 弓兵 / `Archer`
- 弩兵 / `Crossbow`
- 投石車 / `Siege`
- 城市儲存六兵種數量，不再只用單一 `Troops`。
- `Troops` 可作為總兵力相容欄位，但實際兵力結算以六兵種合計為準。
- 騎兵徵募需要城市持有馬匹，並受現有馬匹數量上限限制。
- 弩兵徵募需要 `弓坊`。
- 投石車 / 攻城兵徵募需要 `工坊`。
- 城市之間移動兵力時，可同時移動金、糧、馬與武將。
- 每年 1 月城市馬匹會自然繁殖；目前基礎出生率為 10%，後續可由養馬設施追加加成。

- 步兵 vs 弓兵。
- 槍兵 vs 騎兵。
- 騎兵 vs 弓兵。
- 弓兵 vs 槍兵。
- 弩兵 vs 騎兵。
- 投石車 vs 城防。

### 4.5.2 戰場型態
- Phase 1.5 的 `Attack` 戰鬥分成 `野戰` 與 `攻城戰` 兩種型態。
- 兩者都仍屬戰略層數值結算，不進入獨立戰術地圖。

#### 野戰
- 用途：預留給未來的攔截、出城迎擊、行軍遭遇、城市外接戰。
- 核心規則：
  - 不吃城市 `Defense` 守城加成。
  - `投石車 / Siege` 不提供城防壓制，只視為低機動重裝兵力。
  - 兵種相剋、武將 `Leadership / Combat / Strength`、兵種配比是主要勝負因子。
  - 騎兵、弓兵、弩兵在野戰中的機動與相剋價值應高於攻城戰。

#### 攻城戰
- 用途：當 `Attack` 目標是敵方持有城市時，預設使用 `攻城戰`。
- 核心規則：
  - 吃城市 `Defense` 與守軍兵種配置。
  - `投石車 / Siege` 可壓制守方城防，降低守方有效防禦倍率。
  - 守軍依附城市駐軍作戰，守城方享有防禦優勢。
  - 攻方若獲勝，城市易主，攻方殘存兵力轉為新城留守兵力。
  - 攻方若失敗，生還兵與出征武將返回原城，攜帶金糧只返還部分。

#### 目前實作對應
- 目前專案中的 `Attack` 一律視為 `攻城戰`。
- `CombatResolver` 目前已套用：
  - 城市 `Defense`
  - 投石車壓制城防
  - 六兵種相剋
  - 攻方逐武將配兵後的兵種比例
- `野戰` 尚未獨立落地為可觸發型態，但設計上需保留未來擴充接口。

## 5. 玩家指令
### 5.1 內政
- UI 顯示為 `內政`。
- 內政包含：
- 農業。
- 商業。
- 防衛。
- 治水。
- 建設。
- 玩家選擇工作、武將與執行月份。
- 每名武將同時只能被派任一項工作。
- 內政每月底結算一次。
- 完成每月工作後，城市相關能力提升。
- 未來會加入經驗與職階升級。

### 5.2 徵兵
- 徵兵已整合入 `軍事` dialog。
- 每城每月可執行一次徵兵。
- 徵兵需要指派一名可用武將。
- 指令確認後消耗資源。
- 效果於月底結算。

### 5.3 移動
- 移動已整合入 `軍事` dialog。
- 可移動：
- 兵力。
- 金。
- 糧。
- 武將。
- 目標必須是相連的己方城市。
- 移動於月底結算。
- 被派去移動的武將，本月不可再被派去其他移動 / 攻擊 / 指令。

### 5.4 搜索 / 訪察遷移
- 獨立 `Search` 玩家按鈕已移除 / 隱藏。
- 原本「尋找在野武將」的功能遷移至 `民事 > 訪察民情`。
- 舊 `Search` backend 可暫時保留給 AI / regression 相容，但新玩家流程以 `訪察民情` 為準。

### 5.5 商人
- 玩家可買糧或賣糧。
- UI 會即時顯示金 / 糧增減預覽。
- 交易確認後即時生效。

### 5.6 攻擊
- 攻擊已整合入 `軍事` dialog。
- 目標必須是相連的敵方或中立城市。
- 玩家需要輸入：
- 出兵數。
- 攜帶金。
- 攜帶糧。
- 出征武將列表。
- 至少需要一名武將才能確認攻擊。
- 出征兵力、金、糧會在確認時即時扣除。
- 攻擊於月底發生戰鬥。
- 勝利時：
- 目標城市歸屬改為攻擊方。
- 出征武將留在佔領城市。
- 攜帶金 / 糧帶入佔領城市。
- 失敗時：
- 出征武將返回原城。
- 部分糧草保留，部分損耗。
- log 需要顯示攻防雙方君主名稱，方便閱讀。

### 5.7 人事
- `人事` dialog 包含：
- 賞賜武將。
- 指派官職。
- 開除武將。
- 登用他地武將。

#### 賞賜武將
- 對本城非君主武將賞賜金 / 糧。
- UI 需顯示武將忠誠。
- 賞賜確認後即時消耗城市資源。
- 忠誠提升公式：
- 金 100 -> 忠誠 +1。
- 糧 500 -> 忠誠 +1。

#### 指派官職
- 對本城非君主武將指派職位。
- 目前支援：
- `General`
- `Strategist`
- `Advisor`
- `Governor`
- 未來會改為更完整的官職 / 職階 / buff 系統。

#### 開除武將
- 可將本城己方武將自城市與勢力編制中移除，轉為在野武將。
- 只能選擇本城、同勢力、且目前為 `待命 / Idle` 的武將。
- 只有 `沒有本月命令`、且 `沒有進行中的內政排程` 的武將可被開除。
- 不能開除本勢力君主。
- 開除後：
- 武將自 `City.OfficerIds` 移除。
- 武將自 `Faction.OfficerIds` 移除。
- 武將改為在野武將，並保留在原城市作為可見在野武將。
- 若武將有已裝備道具，裝備會先收回原勢力庫存，再解除裝備狀態。
- UI 規則：
- 開除視窗只顯示符合條件的待命武將。
- 若本城沒有可開除對象，直接提示，不開啟空白名單。

#### 登用他地武將
- 可登用其他勢力或在野的成年武將。
- 隱藏在野人士需要先透過 `訪察民情` 找出行蹤，現身後才會出現在登用列表。
- 在野人士不一定接受登用；拒絕時不會加入城市或勢力。
- 不能登用其他勢力君主。
- 未滿 18 歲不可登用。
- 同勢力武將應使用 `Move` 調動，不使用登用。
- 忠誠高於門檻的武將會拒絕。
- 登用成功後：
- 消耗城市金。
- 武將移至登用城市。
- 武將加入玩家勢力。
- 從原城市 / 原勢力移除。
- 也可對先前被 `開除武將` 轉成在野的武將再次嘗試登用。

### 5.8 民事
- `民事` dialog 包含：
- 救濟。
- 訪察民情。

#### 救濟
- 玩家可投入金 / 糧安撫人民。
- 確認後即時消耗城市資源。
- 城市忠誠提升公式：
- 金 100 -> 城市忠誠 +10。
- 糧 1000 -> 城市忠誠 +10。

#### 訪察民情
- 即時執行。
- 可能結果：
- 發現在野成年人士的行蹤，使其在本城現身。
- 訪察不會直接招募在野人士；玩家需要再用 `人事 > 登用人士` 嘗試登用。
- 城市忠誠提升。
- 發現民間餘糧。
- 收得額外金。
- 採納農業建議，提高農業與忠誠。

## 17. 風險與緩解
- 風險：HUD 與 CommandResolver 變得過大。
- 緩解：以 partial class 或 service 拆分，保持小型功能檔案。
- 風險：Phase 1.5 功能互相牽連，導致 scope creep。
- 緩解：維持 design lock，未列入範圍的功能延後。
- 風險：多語言文字散落在 C#。
- 緩解：所有 UI 文案只放 `locale.json`。
- 風險：資料 JSON 格式錯誤。
- 緩解：啟動前 / 測試中加入 JSON parse 驗證。

## 19. Phase 1.5+ 外交與間諜系統

### 19.1 外交
- 外交系統屬於戰略層玩法，在大地圖與月回合流程內解決，不進入獨立戰鬥場景。
- 目前已提供獨立的 `外交` 指令分類。
- 目前基線版已實作：
- `同盟`
- `休戰`
- `贈禮`
- `索貢`
- `毀約`
- 後續仍可再擴充更進階的外交行動。
- 基本外交行動：
- `同盟`：雙方進入友好或同盟狀態，在固定月數內大幅降低互相進攻傾向。
- `停戰`：雙方暫停交戰，但不等同正式同盟。
- `進貢 / 贈禮`：目前已支援送出 `金`、`糧`、`馬` 以改善關係；`道具` 仍屬後續可擴充項。
- `威逼 / 要求`：向弱勢勢力索取資源、政治讓步或投降。
- `毀約`：主動解除同盟或停戰，通常伴隨信任與關係懲罰。
- 外交成功率主要受以下因素影響：
- 君主 `魅力`
- 外交使者或軍師的 `智力 / 魅力`
- `軍師階 / 文官階` 加成
- 雙方目前關係
- 雙方勢力強弱差距
- 近期戰爭與背約紀錄
- 外交命令在 `月底` 結算，與其他戰略命令共用月末流程。
- 若 AI 對玩家勢力提出 `同盟 / 休戰 / 贈禮 / 索貢`，應進入 `玩家可回應提案` 流程：
- AI 先正常排定外交命令。
- 月底若目標為玩家勢力，先暫停流程並顯示提案彈窗。
- 玩家可選擇 `接受` 或 `拒絕`。
- 玩家接受時，依原本外交規則結算。
- 玩家拒絕時，提案不生效；若為 `贈禮`，需返還 AI 原城市預留的 `金 / 糧 / 馬`。
- 此提案流程目前涵蓋 `同盟 / 休戰 / 贈禮 / 索貢`。
- `毀約` 為通知制，只提示玩家，不提供拒絕。
- 外交狀態至少應追蹤：
- 關係層級（`敵對 / 中立 / 友好 / 同盟`）
- 條約種類
- 剩餘月數
- 背約或失信懲罰

### 19.2 間諜系統
- 間諜系統屬於戰略層的祕密行動，應與公開外交分開處理。
- 目前已提供獨立的 `間諜` 指令分類，可從 HUD 直接開啟。
- 目前基線版已實作：
- `偵查`
- `破壞`
- `煽動`
- 每次間諜任務需要指派一位武將，並在 `月底` 結算。
- 基準規則下，`君主` 不可直接執行間諜任務。
- 間諜任務成功率主要受以下因素影響：
- 執行武將 `智力`
- 執行武將 `魅力`
- `間諜階 / 間諜號` 與既有屬性加成
- 目標城市 `忠誠`
- 目標城市 `防禦`
- 目標城市整體警戒能力
- 兩勢力目前外交關係
- 每項間諜任務都帶有 `暴露風險`。
- 目前基線版的暴露處理為：
- 與目標勢力 `關係值下降`
- 執行武將 `忠誠下降`
- 成功與失敗都可能暴露，但失敗時懲罰更重。
- 後續高階版仍可再擴充為：
- 間諜身份暴露
- 任務失敗
- 被捕
- 被處決
- 生還返回但忠誠下降

### 19.3 間諜任務種類
- `偵查`：
- 目前基線版已實作，會回報目標城市的 `主事者`、`金`、`糧`、`總兵力`、`防禦`、`忠誠`、`武將數`。
- 完整設計仍可再擴充為揭露 `六兵種數量`、`守城武將細節`、`防災`、`進行中的內政`，以及 `在野 / 隱藏武將線索`，並讓情報維持數月。
- `破壞`：
- 目前基線版已實作，會破壞目標城市的 `糧`、`金`、`防禦`。
- 完整設計仍可再擴充為影響 `防災`、`兵種儲備`、`工坊 / 弓坊`，或拖慢目前內政進度。
- `策反`：
- 目前基線版以 `煽動` 形式實作，先降低目標城市 `忠誠`。
- 完整設計仍可再擴充為降低目標武將忠誠，並嘗試讓低忠誠武將、在野武將或地方民心轉向我方。
- `行刺`：
- 尚未實作，保留為後續高風險任務。
- `行刺` 應具有最高的失敗與暴露風險，並受到目標忠誠、城市防備、護衛與身份地位強烈影響。

### 19.4 設計約束
- 外交與間諜應優先共用既有 `月底排程`、`log`、`command resolver` 架構。
- 複雜的外交與間諜表單 UI 應使用 `Window`，不使用 `AcceptDialog`。
- 所有外交與間諜可見文字必須放在 `data/localization/locale.json`。

### 19.5 指派武將與行動月數
- 外交行動必須指派一位武將執行，通常應由 `君主以外` 的使者、軍師或文官出任。
- 間諜行動也必須指派一位武將執行，且執行中的武將在任務期間不可再接其他月令。
- 外交與間諜都應支援兩種時間模型：
- `單月行動`：當月下令，月底結算結果。
- `多月行動`：持續滲透、斡旋、施壓、送禮、離間等，需要累積多月後才結算或逐月累積成功率。
- 多月外交與多月間諜行動應記錄至少以下資料：
- 指派武將 `OfficerId`
- 來源勢力 / 來源城市
- 目標勢力 / 目標城市 / 目標武將
- 行動種類
- 已執行月數
- 剩餘月數
- 是否暴露
- 目前成功率修正
- 建議的時間模型：
- `偵查`：可做單月，也可做多月；時間越久，情報越完整。
- `破壞`：通常至少需要一段準備期，再於月底結算破壞結果。
- `策反`：偏向多月行動，逐月累積影響力與成功率。
- `行刺`：可作高風險單月突擊，也可先多月佈局，再選擇執行月份下手。

### 19.6 情報可視範圍與開發用 God Mode
- 在正常遊戲規則下，`他方勢力`、`他方城市`、`他方武將` 的詳細資訊預設應為隱藏。
- 若沒有成功進行 `偵查` 或其他間諜情報行動，玩家只能看見有限的公開資訊，其餘欄位應顯示為 `??` 或未知狀態。
- 預設應隱藏或模糊的資訊包括：
- 城市 `金`、`糧`、兵力總數、六兵種構成
- 城市 `防禦`、`防災`、工坊 / 弓坊、進行中的內政
- 他方武將的 `忠誠`、`官職`、`職階`、`稱號`、裝備 / 道具
- 他方勢力的真實軍力、後勤儲備與內政狀態
- 可保留為公開資訊的內容包括：
- 城市名稱
- 所屬勢力
- 基本外交關係
- 城市是否存在、是否相鄰
- 已經透過劇情、初始設定或既有情報得知的公開武將姓名
- `偵查` 應是揭露他方城市 / 武將詳細資訊的主要手段。
- 情報應有 `時效性`：
- 已揭露資訊可維持若干月
- 時間過久後可視為過時，需重新偵查
- 多月偵查或高階間諜可揭露更完整資料
- 系統應保留一個 `開發 / 測試專用 God Mode` 或 `View All Information` 開關。
- 啟用後，可直接查看所有城市、勢力、武將、兵種、道具、排程資訊，不受情報迷霧限制。
- 此模式僅供開發、測試、平衡調整、debug 與 UI 驗證，不屬於正式遊戲預設規則。
## 18.2 2026-05-09 諜報暗殺、君主繼承與勢力滅亡

### 18.2.1 `Spy -> Assassination`
- `Spy` 進階動作已新增 `Assassination`。
- 玩家現在可在 `Spy -> Assassination` 介面中直接手選目標官員。
- AI 在排定 `Assassination` 時，也會同時指定優先暗殺目標。
- 若未指定目標官員，系統才會退回舊的自動挑選邏輯。
- 月末結算成功時，會優先處理指定目標；若沒有指定，則從目標城內挑選一名高價值武將作為暗殺對象。
- 目標挑選優先順序：
  - 若城內有君主，君主可成為優先暗殺目標。
  - 否則依武將價值排序，綜合考量 `Combat / Leadership / Intelligence / Politics / Charm`。
- 暗殺成功後：
  - 武將自 `City.OfficerIds` 移除。
  - 武將自 `Faction.OfficerIds` 移除。
  - 已裝備道具會先回收到原勢力庫存；若勢力已滅亡，則道具歸零為未持有。
  - 武將會標記為已死亡，不再回到自由武將流動系統。

### 18.2.2 君主死亡後處理
- `Assassination` 現在允許殺死君主。
- 若被暗殺者是 `Faction.RulerOfficerId`，會立刻進入君主死亡後處理。
- 戰鬥結算現在也會檢查參戰君主是否陣亡。
- 目前規則為：
  - 若某一方參戰兵力在該場戰鬥中被打到全滅
  - 且該方參戰武將名單內包含君主
  - 則該君主視為戰死，並進入同一套君主死亡後處理流程
- 因此目前「君主死亡 -> 繼承 / 滅亡」的後續規則，已同時適用於 `Assassination` 與 `Attack` 戰鬥結算。

### 18.2.3 AI 勢力繼承規則
- 若死亡君主屬於 `AI faction`，系統會自動選出新君主。
- 候選條件：該勢力仍存活、仍屬該勢力、且尚未死亡的武將。
- 繼承優先順序：
  - `Role == Lord / Ruler`
  - 否則 `Leadership + Intelligence + Politics + Charm` 最高
  - 同分再比 `Loyalty`
- 選定後會同步更新：
  - `Faction.RulerOfficerId`
  - 新君主 `Role = Lord`
  - 勢力名稱
- 勢力名稱現行規則：
  - 繁中：`{新君主姓名}軍`
  - 英文：`{NewRulerName} Forces`

### 18.2.4 玩家勢力繼承規則
- 若死亡君主屬於 `Player faction`，不會自動指派新君主。
- 月末流程會暫停，彈出 `君主繼承` 視窗。
- 視窗會依同一套優先順序列出候選武將，供玩家手動選擇。
- 玩家確認後，才會正式完成繼位並繼續月末後續流程。
- 玩家完成繼位時，也會同步更新新君主官職與勢力名稱。

### 18.2.5 無人可繼承時的勢力滅亡
- 若君主死亡後，該勢力已無其他可繼位武將，則直接判定勢力滅亡。
- 目前採用的滅亡處理是：
  - 該勢力所有城市轉為中立
  - `Faction.RulerOfficerId` 清空
  - `Faction.OfficerIds` 清空
  - 與該勢力相關的外交關係全部清除
  - 該勢力尚未結算的 `PendingCommands` 全部取消
  - 該勢力相關的待處理繼承記錄清除
- 本版尚未採用「由鄰近敵方自動接收城市」規則，先以 `全部轉中立` 為準。

### 18.2.6 UI / 流程接線
- 玩家君主死亡後的繼承視窗屬於月末結算中斷流程的一部分。
- 它會與既有的：
  - `AI -> 玩家外交提案`
  - `玩家防守彈窗`
  - `月末非戰鬥 / 戰鬥結算`
  共用同一條「中斷後再繼續」的 resolution flow。
- 若玩家君主是在攻城戰或守城戰中死亡，也會在該次月末戰鬥結算後立即中斷，彈出 `君主繼承` 視窗，再由玩家決定繼位者。

### 18.2.7 驗證重點
- `Assassination` 成功後，目標武將不會殘留在城市或勢力名單。
- 戰鬥中若參戰君主所屬兵力被全滅，君主會正確標記死亡。
- `AI faction` 君主死亡後會自動產生新君主。
- `Player faction` 君主死亡後會出現候選列表供玩家選擇。
- 無人可繼承時，勢力會正確滅亡，且城市、外交、pending command 狀態會同步清理。
