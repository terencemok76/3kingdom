# AI 任命手測清單

更新日期：2026-05-25

## 1. 目的

- 驗證 AI 勢力目前的 appointment 行為是否正確。
- 本清單聚焦：
  - `丞相 / 首席軍師` 自動任命
  - `太守` 自動任命
  - 太守離城後自動補任
  - 任命 log 與實際資料是否一致

## 2. 本輪驗證範圍

- 已納入：
  - AI 勢力中央職自動任命
  - AI 城市太守自動任命
  - 太守離城 / 死亡 / 被挖角 / 被解雇後自動補任
  - 自動補任後授權 / 月計畫延續規則
  - 日誌顯示
- 不納入：
  - AI `None / Full` 授權切換策略優化
  - 太守 personality / characteristic 深化
  - Phase 3 的 comment / buff / event / fog 擴充

## 3. 測試記錄格式

- 每條測試建議記錄：
  - `測試項`
  - `前置條件`
  - `操作步驟`
  - `預期結果`
  - `實際結果`
  - `PASS / FAIL`
  - `備註`

## 4. 測試環境建議

- 使用可快速連續 `End Turn` 的存檔或新局。
- 建議保持：
  - `Log` 面板可見
  - `城市資訊`
  - `View -> Cities`
  - `View -> Faction Officers`
- 若要確認 appointment 寫入：
  - 觀察 HUD 城市資訊中的 `太守`
  - 觀察人事 / 檢視類 UI 的職位欄

## 5. 核心測試項

### 5.1 AI 中央職自動任命

- 前置條件：
  - 選一個 AI 勢力
  - 該勢力目前沒有 `丞相` 或 `首席軍師`
- 操作步驟：
  - 直接 `End Turn`
- 預期結果：
  - AI 會在該回合自動任命缺少的中央職
  - log 會出現對應任命訊息
  - 實際 faction 資料中 `ChancellorOfficerId / ChiefStrategistOfficerId` 有寫入
  - 被任命武將的 `Appointments` 也正確新增

### 5.2 AI 城市自動任命太守

- 前置條件：
  - AI 勢力擁有至少一座沒有太守的城市
- 操作步驟：
  - 直接 `End Turn`
- 預期結果：
  - AI 會為該城自動任命太守
  - log 會出現太守任命訊息
  - 城市資訊會顯示新太守
  - 被任命武將持有 `Governor` appointment

### 5.3 AI 多城補太守

- 前置條件：
  - AI 勢力有兩座以上城市都沒有太守
- 操作步驟：
  - 直接 `End Turn`
- 預期結果：
  - AI 會逐城嘗試補任太守
  - 不會只補第一座城
  - 不會把同一位武將同時任成多城太守

### 5.4 AI 不會把君主任成太守

- 前置條件：
  - 觀察 AI 君主所在城市
  - 城內仍有其他可用武將
- 操作步驟：
  - 直接 `End Turn`
- 預期結果：
  - AI 不會把 `君主` 任成太守
  - 會優先選其他城內可用武將

### 5.5 中央職與太守不互相衝突

- 前置條件：
  - AI 勢力需要補中央職，且也有城市缺太守
- 操作步驟：
  - 直接 `End Turn`
- 預期結果：
  - AI 先補中央職，再補各城太守
  - 中央職保留人選不應被優先拿去補太守
  - 若城內只有中央職人選可用，可接受 fallback，但 appointment 不應錯亂

### 5.6 太守移動離城後自動補任

- 前置條件：
  - 找一座已有太守的城市
  - 讓該太守因 `Move` 離開原城
- 操作步驟：
  - 結算到月末，完成移動
- 預期結果：
  - 原太守會失去原城 `Governor`
  - 原城若仍有合格武將，系統會自動補任新太守
  - log 會追加：
    - 自動改任新太守
    - 或無人可補任、太守空缺

### 5.7 太守被挖角後自動補任

- 前置條件：
  - 目標城已有太守
  - 使該太守被他勢力成功登用
- 操作步驟：
  - 完成登用結算
- 預期結果：
  - 原城會失去原太守
  - 若城內有其他合格人選，會自動補任
  - log 會出現補任或空缺訊息

### 5.8 太守被解雇後自動補任

- 前置條件：
  - 某城已有太守
- 操作步驟：
  - 對該太守執行解雇
- 預期結果：
  - 若城內尚有合格武將，會立即自動補任
  - 若沒有，則轉為空缺
  - log 會追加補任結果

### 5.9 太守死亡 / 暗殺後自動補任

- 前置條件：
  - 目標城已有太守
- 操作步驟：
  - 令該太守死亡
  - 方式可為：
    - 戰死
    - `Assassination`
- 預期結果：
  - 原太守從城市與 faction 資料中移除
  - 原城若仍有合格武將，會自動補任
  - log 會追加補任或空缺訊息

### 5.10 自動補任後授權延續

- 前置條件：
  - 該城原本已有 `Half` 或 `Full` 太守授權
  - 再讓原太守離城
- 操作步驟：
  - 觀察自動補任後的城市狀態
- 預期結果：
  - 若補任成功：
    - `Full`：可依新太守重新生成自治 plan
    - `Half`：保留玩家指定 plan 資料，但舊 schedule 已中止，待新太守重新派工
  - 若無可補任人選：
    - 授權清回 `None`

### 5.11 log 與資料一致性

- 操作步驟：
  - 針對上面每一種補任情境，逐條核對 log
- 預期結果：
  - 若 log 顯示已自動改任某人：
    - 該武將實際持有 `Governor`
    - HUD / View 可見一致結果
  - 若 log 顯示無可補任人選：
    - 城市確實沒有太守
    - 授權狀態符合規則

## 6. 通過標準

- AI 能自動補齊缺少的中央職
- AI 能為缺太守城市自動任命太守
- 太守離城 / 死亡 / 被挖角 / 被解雇後，能正確自動補任或轉空缺
- 不會錯把君主任成太守
- 不會出現 appointment 重複或資料殘留
- log 與實際資料一致

## 7. 建議補測順序

1. `AI 中央職自動任命`
2. `AI 城市自動任命太守`
3. `AI 多城補太守`
4. `太守移動離城後自動補任`
5. `太守被挖角 / 解雇 / 死亡後自動補任`
6. `自動補任後授權延續`
7. `log 與資料一致性`
