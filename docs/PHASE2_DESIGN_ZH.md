# 三國策略遊戲 Phase 2 設計文件（繁體中文）

## Phase 2 設計鎖定
- 設計鎖定標籤：`Phase2-Design-Locked-v1`
- 設計鎖定日期：`2026-05-10`
- 目的：在 Phase 2 實作前先定義範圍、資料模型、UI 流程與驗證方式，避免直接邊做邊改。
- 狀態：設計鎖定中。後續 Phase 2 功能應先依此文件確認，再進入實作。
- 備註：目前 codebase 已有 `中央任命 / Advisor` 的早期原型；若與本文件衝突，以本文件後續確認版本為準。

## 1. Phase 2 目標
- 在 Phase 1.5 可玩基線之上，加入更明確的 `中央任命 / 戰略建議 / 勢力治理` 層。
- 讓玩家不只管理城市，也開始管理整個勢力的中央職位與決策傾向。
- Phase 2 第一波不追求完整政治模擬，而是先建立：
  - 唯一中央職位
  - 玩家任命流程
  - 顧問建議文字
  - 後續 buff 與事件鏈可擴充的資料結構

## 2. Phase 2 範圍

### 2.1 本階段預計納入
- 中央職位系統：
  - `丞相 / Chancellor`
  - `首席軍師 / Chief Strategist`
- 地方城市職位系統：
  - `太守 / Prefect`
- 每個勢力唯一職位規則
- 每座城市可有 `1` 位太守
- 玩家手動任命 UI
- 顧問建議顯示
- 玩家授權地方太守設定城市月計畫
- 中央職位持有人失效時的清理規則
- 地方太守持有人失效時的清理規則

- 文件化測試與 playtest 檢查項

### 2.2 本階段先不納入
- 完整中央官制樹
- 多層級軍師群 / 文官群
- 官職薪俸、嫉妒、派系鬥爭
- 顧問插話事件鏈
- 真正複雜的戰略 AI 推演
- 依職位觸發的專屬指令樹
- 太守專屬事件鏈與完整自治 AI 性格模組

## 3. 中央職位系統

### 3.1 職位清單
- `丞相 / Chancellor`
  - 定位：內政總管、文官核心、穩定度與資源方向的首席建議者
- `首席軍師 / Chief Strategist`
  - 定位：軍事與戰略總參、邊境與攻防方向的首席建議者
- 補充：
  - 兩個職位可由同一名武將兼任
  - 即使由同一人兼任，兩個職位的 function 與 comment 仍應分開處理，不合併為單一顧問輸出

### 3.2 唯一性規則
- 每個勢力同時最多只有：
  - `1` 位丞相
  - `1` 位首席軍師
- 同一名武將：
  - `設計確認`：**可同時兼任丞相與首席軍師**
- 君主：
  - `v1 建議規則`：不可直接兼任丞相或首席軍師

### 3.3 任命資格
- 武將必須屬於該勢力
- 武將必須存活
- 武將不可為君主
- `v1 建議` 不限制武將目前 `Role`
- `v1 建議` 不要求同城，但 UI 可先從玩家選中城市作為主要入口

### 3.4 解除 / 失效規則
- 若持有人：
  - 戰死
  - 被暗殺
  - 被開除
  - 被登用到其他勢力
  - 勢力滅亡
  - 繼位成新君主
- 對應中央職位需自動清空
- Player 可主動對單一武將解除既有 appointment
  - `v1 實作`：目前支援解除 `太守 / 軍師 / 丞相 / 首席軍師`
  - 解除成功後，應立即刷新該武將的 appointment 顯示與 faction / city 關聯狀態

## 3A. 地方太守系統

### 3A.1 職位定位
- `太守 / Prefect`
  - 定位：單一城市的地方主管，負責該城月度方針與地方執行節奏
- 此職位與 `丞相 / 首席軍師` 不同：
  - 丞相 / 首席軍師屬於 faction-level 中央建議層
  - 太守屬於 city-level 地方執行層

### 3A.2 唯一性規則
- 每座城市同時最多只有：
  - `1` 位太守
- 同一名武將：
  - `v1 建議`：不可同時擔任多座城市的太守
- 是否可同時兼任中央職位：
  - `設計暫定`：可，後續若實作複雜度過高再另行收斂

### 3A.3 任命來源
- Player 可以為自己 faction 轄下每座城市任命太守
- AI 也可以為自己 faction 轄下每座城市任命太守
- 太守屬於 faction 內部任命，不是獨立勢力角色

### 3A.4 任命資格
- 武將必須屬於該勢力
- 武將必須位於該城市，或被視為該城市之有效行政人員
- 武將必須存活
- 君主是否可兼任太守：
  - `設計暫定`：可，除非後續 UI / AI 管理負擔過高

### 3A.5 解除 / 失效規則
- 若太守：
  - 戰死
  - 被暗殺
  - 被開除
  - 被登用到其他勢力
  - 離開該城且不再屬於該城行政歸屬
  - 勢力滅亡
- 對應城市的太守職位需自動清空
- 若太守只是「離開該城」，但原勢力與該城市仍存在：
  - 系統應優先從同城現有武將中自動補任新太守
  - 若同城沒有可任命對象，才將太守職位設為空缺
- `v1 建議`：自動補任時優先選擇同城中最適合行政管理的武將
  - 可先以 `Politics + Intelligence + Loyalty` 作為基礎排序
  - 若同分，再比較 `Charm`
- Player 可主動解除城市太守
  - 解除後，該城市 `PrefectAuthorizationType` 必須立即重設為 `None`
  - HUD / 人事畫面 / 城市狀態顯示需同步更新

### 3A.6 太守月計畫
- 每位太守可對其所屬城市持有 `月計畫 / monthly plan`
- 月計畫是 city-level 的執行傾向，不是一次性指令
- v1 可先將月計畫理解為：
  - 該城本月優先要做什麼
  - 若系統允許自動執行，該城優先消耗可用行動去推進哪類工作
- v1 建議月計畫類型：
  - `農業`
  - `商業`
  - `防禦`
  - `徵兵`
  - `治安 / 民心`
  - `休養 / 平衡`

### 3A.7 授權規則
- Player 與 AI 都可以有太守，但 `能否自行設定月計畫` 取決於授權狀態
- Player faction：
  - Player 可選擇某城市的授權模式：
	- `未授權 / None`
	- `半授權 / Half`
	- `全授權 / Full`
  - `未授權`：
	- 月計畫由 player 直接指定
	- 太守不自動決策
  - `半授權`：
	- player 指定城市目標與計畫期
	- 太守負責監督執行，並從當月可用武將中指派適合人選
  - `全授權`：
	- 太守可依規則或傾向自動決定該城月計畫
	- 太守負責執行期內的派工與重派
  - 若 player 曾手動覆蓋月計畫：
	- 視為直接改變該城目前生效中的 plan
	- 不需再次授權
	- `v1 設計`：手動覆蓋後，該 plan 持續生效，直到 player 再次更改，或系統依既定規則進入下一次可重算節點
- AI faction：
  - AI 視為天然擁有授權能力，可直接讓太守依 AI 邏輯設定月計畫
  - 不需模擬「再由 AI 上級額外點一次授權」的操作流程，除非後續想做更細緻的 AI 官僚層
  - `v1 實作狀態`：
	- 目前 AI 城市若已有太守，會依 `Full` 邏輯自動生成自治月計畫
	- 目前尚未完整實作 AI 主動判斷 `None / Half / Full` 三種授權模式
	- 因此現階段 AI 授權較接近「有太守即可自治」，而非完整模擬玩家式授權切換

### 3A.8 Player 與 AI 差異
- Player 的授權是一個明確操作選項，重點在於：
  - 玩家願不願意把單城經營決策下放
  - 玩家保留直接接管的能力
- AI 的授權則偏向系統行為，重點在於：
  - AI 是否使用太守作為城市月計畫的責任節點
  - 不強求 AI 走與玩家完全相同的手動授權 UI
- AI behavior style：
  - AI 太守不應全部表現為單一模板
  - 可依武將能力與性格，分成不同決策風格，例如：
	- 文治型：偏 `農業 / 商業 / 治安`
	- 守成型：偏 `防禦 / 平衡`
	- 進取型：偏 `徵兵 / 前線準備`
  - 同一勢力內不同城市，也可因太守不同而呈現不同月計畫傾向
- `v1 實作狀態`：
  - 目前 AI 太守月計畫主要受：
	- 城市數值
	- 太守能力值
  - 影響
  - 尚未完整做到：
	- AI 主動切換授權模式
	- `Half authorize` 的獨立 AI 策略語意
	- 依 personality / characteristic 明顯區分治理風格的完整版本

### 3A.7A 授權 Plan 執行狀態
- `授權模式` 與 `plan 執行狀態` 必須分開
- 授權模式決定：
  - 誰負責決定月計畫
  - 誰負責派工
- 執行狀態決定：
  - 該計畫目前是否正在跑
  - 本月是否暫停或略過
- `v1 建議`至少有：
  - `Running`
  - `Paused`
- 另外需要支援一個「只影響本月」的操作：
  - `取消本月執行`
  - 此操作不是取消授權，也不是刪除整個 plan
  - 只是讓該 plan 本月不執行，並釋放原執行武將
  - 下月可重新派工後繼續跑

### 3A.7B Pause / Resume / Cancel Current Month
- `Pause`
  - 不移除授權模式
  - 不刪除當前月計畫
  - 只是暫停 plan 執行
  - 暫停後原執行武將應立即釋放，可改做其他任務
- `Pause` 也可能由系統自動觸發，而不一定是玩家手動點擊：
- 例如城市當月金不足，無法支付該內政 plan 的 `每月投入金`
- `Resume`
  - 恢復原計畫
  - 太守不必綁定原執行武將
  - 系統應允許太守依當下可用武將重新指派最適人選
- 若 `Pause` 原因是 `資金不足`
- 則當後續月份城市資金恢復足夠，且能重新找到可用執行武將時，可由系統自動恢復
- `Cancel Current Month`
  - 取消本月這一次執行
  - 不等於 `Pause`
  - 不等於 `Cancel Authorization`
  - 不等於 `Terminate Plan`
  - player 可在取消後，立刻把原執行武將改派去做其他事
- `Terminate Plan`
  - 代表整個內政 / 授權 plan 被明確結束
  - 不再保留剩餘月數
  - 若之後要再跑，需重新建立 plan

#### 目前實作補充
- 目前 `內政 / 授權 plan` 的成本語意為 `每月投入金`
- 不是建立 plan 時一次扣完整總預算
- 若設定 `3` 個月、`每月投入金 500`
- 則每月底分別檢查並扣除 `500`
- 總成本為 `1500`
- 若其中某月金不足，該 plan 轉為 `Paused`
- 之後資金恢復時可自動續行

## 4. UI 設計

### 4.1 入口
- 左側城市指令列新增 `Advisor / 參謀` 按鈕
- 入口定位：
  - 雖然按鈕可先放在城市指令列，但其功能定位為 **全國性 / 勢力層級指令**
  - 玩家進入後，操作對象應為整個 faction，而不是單一城市內政子功能
  - 後續若做成勢力層介面，可搬到 `View` 或新 `Court` 視窗

### 4.2 Advisor 視窗
- 功能：
  - 查看目前 `丞相`
  - 查看目前 `首席軍師`
  - 從候選武將中任命
- 視窗定位：
  - 這是 faction-wide 的中央任命畫面
  - 候選名單應以該勢力全體武將為基礎，而不是只限當前城市
- 建議欄位：
  - 武將名
  - 官職
  - 忠誠
  - `STR / INT / CHA / LEA / POL`
  - 目前是否已持有中央職位

### 4.2B 指派職位視窗
- 功能：
  - 對單一武將執行 `任命職位`
  - 對單一武將執行 `解除職位`
  - 查看該武將目前已持有的 appointments
- `v1 實作行為`：
  - 可先不選武將，保持 `未選擇`
  - 可透過 `清除選擇` 回到未選武將狀態
  - 選將名單只顯示 `本勢力已雇用武將`
  - 不顯示尚未登用、僅暫時停留在城市中的人物
  - 任命與解除分成兩個獨立下拉與兩個獨立確認按鈕
  - `任命職位` 清單不重複列出該武將已持有的 appointments
  - `解除職位` 清單只顯示該武將目前真的持有的 appointments
  - 若沒有可解除職位，解除按鈕應禁用
  - 任命 / 解除完成後，視窗不自動關閉
  - 結果訊息直接顯示於視窗內，方便玩家連續處理同一武將或下一位武將
- 建議欄位：
  - 已選武將
  - 目前持有職位
  - 待任命職位
  - 待解除職位
  - 當前操作結果訊息

### 4.2A 太守 / 月計畫視窗
- 功能：
  - 查看每座城市目前太守
  - 為單一城市任命太守
  - 查看該城市目前月計畫
  - 指定玩家是否授權該太守自訂月計畫
  - 在未授權情況下由玩家直接指定月計畫
  - 對當前 plan 執行 `Pause / Resume / Cancel Current Month / Terminate`
- 視窗定位：
  - 這是 city-level 的地方治理介面
  - 可從城市視角進入，因為其關心的是單城執行
- 建議欄位：
  - 城市名
  - 太守姓名 / 未任命
  - 當前授權狀態
  - 當前月計畫
  - 當前 plan 執行狀態
  - 候選武將

### 4.3 城市資訊面板
- 左側城市資訊面板顯示：
  - `丞相：姓名 / 未任命`
  - `建議：一句內政建議`
  - `首席軍師：姓名 / 未任命`
  - `建議：一句戰略建議`
- 不再要求於左側城市資訊面板顯示 `city officers` 名單
- 設計原則：
  - 左側面板應聚焦於城市摘要、中央 comment、與當前城市決策資訊
  - 武將清單改由其他視窗承載，例如 `View`、`Personnel`、或後續專門城市管理畫面
- 補充規則：
  - 面板顯示的是「目前可提供的 faction comment」
  - 若現任 `丞相` 或 `首席軍師` 正在出征 / 戰場 / 長時程軍事行動中，則視為當月 **不可提供 comment**
  - 若正職無法評論，系統可改由較次軍師、官員，或君主提供替代 comment
  - comment 來源不必與職位持有者完全綁死；重點是反映 faction 當月仍有中央判斷聲音

## 5. 建議句規格

### 5.1 丞相建議方向
- 忠誠偏低時：
  - 優先提示 `救濟 / 訪察民情 / 穩定民心`
- 糧食偏低時：
  - 優先提示 `農業 / 運糧`
- 金偏低時：
  - 優先提示 `商業`
- 人口偏低時：
  - 提示避免消耗戰
- 狀態平衡時：
  - 提示均衡發展

### 5.2 首席軍師建議方向
- 鄰城有敵且我方優勢時：
  - 提示可考慮進攻
- 鄰城有敵但我方防禦薄弱時：
  - 提示先補城防
- 邊境有敵但未到進攻時機：
  - 提示維持戰備
- 內部不穩時：
  - 提示避免對外擴張
- 無急迫戰事時：
  - 提示先做外交 / 間諜佈局

### 5.3 顯示原則
- 建議句先做成 `規則式模板`
- Phase 2 不做生成式長文
- 每次只顯示：
  - `1` 句丞相建議
  - `1` 句首席軍師建議
- 人物特性影響原則：
  - comment 不只由局勢決定，也應受發言武將本身能力與性格影響
  - 同一局勢下，不同武將可給出不同品質、不同傾向的 comment
  - 因此 `comment` 應理解為：
	- `局勢判斷`
	- 加上 `人物濾鏡`
- 分工原則：
  - `丞相` comment 專注於內政、民心、資源、治理方向
  - `首席軍師` comment 專注於軍事、邊境、攻防、戰略方向
  - 即使同一名武將同時兼任兩職，系統仍應分別輸出兩條 comment
  - UI 上仍以 `丞相` 與 `首席軍師` 兩個欄位呈現，不因兼任而合併
- comment 來源規則：
  - 預設優先使用現任 `丞相` / `首席軍師`
  - 若正職正在戰場或無法參與 faction-level 決策，該 comment 可改由代理人提供
  - 代理人可來自：
	- 次軍師
	- 其他高階官員
	- 君主
  - UI 可先顯示職位名稱對應 comment，不必在 v1 額外展開完整代理身份來源
- 時間規則補充：
  - 需假設一次 battle 可能跨越 `1` 個月以上
  - 因此 comment 產生邏輯不能單純假設「出征後當月立刻返回」
  - 若武將仍在外作戰或處於未結束軍事任務中，應持續視為不可提供中央 comment

### 5.3A Suggestion Priority
- `Advisor` 是 faction-level suggestion
- `太守` 是 city-level suggestion
- suggestion 的優先順序不應只由固定系統表決定，還需參考發言者本身 characteristic
- 設計原則：
  - 同一局勢下，不同人物可因能力與性格不同，而判斷不同優先事項
  - 因此 suggestion priority 應理解為：
	- `局勢客觀壓力`
	- 加上 `officer characteristic 權重`
- 例如：
  - 高 `Intelligence` 官員較能正確抓出真正最高優先問題
  - 高 `Ambition` 官員可能更常把進攻或擴張排在前面
  - 高 `Caution` 官員可能更常把內部穩定、防禦、補給排在前面

### 5.3B Confidence / Stance
- suggestion 的 `confidence / stance` 應參考發言者 characteristic，而非固定由事件種類決定
- 可反映在語氣或表述強度上，例如：
  - `建議`
  - `強烈建議`
  - `警告`
- 設計原則：
  - 高能力且高適性的官員，comment 可更明確、更有把握
  - 普通能力官員，comment 可較保守、較模糊
  - 高 `Boldness` 或高 `Ambition` 官員，語氣可更強勢
  - 高 `Caution` 官員，語氣可更審慎

### 5.3C Advisor vs Prefect Conflict
- 中央 `Advisor` comment 與地方 `太守` 月計畫可以不一致
- `v1 設計確認`：
  - 中央 comment 不直接強制覆蓋地方計畫
  - 只有在 player 手動介入時，才改變城市 plan
- 設計意義：
  - `Advisor` 提供方向判斷
  - `太守` 負責地方執行
  - 二者可存在張力，這是系統特色，不必強行抹平

### 5.3D Fallback Speaker
- 若原本應發言的 `丞相`、`首席軍師`、或 `太守` 當月無法提供 suggestion，系統可啟用 fallback speaker
- fallback speaker 僅代表 comment 來源切換，不代表正式官位轉移
- fallback speaker 仍應受其自身 characteristic 影響，因此 comment 品質與方向可能改變

### 5.3E Bad Suggestion Tolerance
- 系統設計上不要求所有 suggestion 永遠正確
- 低能力、低適性、或性格偏激的官員，可產生品質較差的 suggestion
- `v1 建議`：
  - 允許輕度偏差或保守誤判
  - 避免過度誇張到讓玩家覺得系統隨機亂講
- 目標是讓人物能力真正影響 decision quality，而不是所有 comment 都是最佳解提示器

### 5.4 人物能力與性格對 comment 的影響
- comment 的內容品質應受武將能力值影響，至少包含：
  - `Intelligence`
  - `Politics`
  - `Leadership`
  - `Charm`
- 後續若資料模型允許，也可納入人格傾向，例如：
  - `Ambition`
  - `Loyalty`
  - `Caution / Boldness`
  - `Mercy / Harshness`
- 設計原則：
  - 高能力武將的 comment 應更準確、較可靠、較能抓到真正優先問題
  - 普通能力武將的 comment 應較籠統、較保守，或只指出表層問題
  - 低能力或不適任武將的 comment 可以不夠精準，甚至帶有輕微誤導性

### 5.5 不同能力層級的 comment 風格
- `高 Intelligence / 高 Politics` 的內政型官員：
  - 較容易指出真正瓶頸
  - 建議較聚焦，可信度較高
  - 例如能分辨「糧食短缺」與「忠誠低落」哪個更急迫
- `普通 Intelligence` 的官員：
  - comment 可維持正確大方向，但較偏通用模板
  - 例如只會說「應穩定內政」而不指出更精準的優先序
- `高 Intelligence / 高 Leadership` 的軍事型官員：
  - 較能正確判斷攻守時機、邊境壓力、戰線風險
  - 在相同局勢下，comment 較具行動性與判斷力
- `能力不足` 的軍事型官員：
  - 可能只會給出保守或模糊建議
  - 在邊境壓力複雜時，可能無法正確指出最佳方向

### 5.6 性格傾向對 comment 的影響
- 除了能力高低，comment 也可受人物性格影響
- 例如：
  - `Ambition` 高者：
	- 更傾向進取、擴張、主動建功
  - `Loyalty` 高者：
	- 更傾向穩健維持 faction 整體安全與秩序
  - `Caution` 高者：
	- 更常提出保守、防守、先補內部問題的 comment
  - `Boldness` 高者：
	- 更常在優勢不完全明確時仍鼓勵冒進
- 這些性格差異不一定代表 comment 一定正確或錯誤，而是影響其建議方向

### 5.7 準確度與可靠度
- 設計上可將 comment 視為有隱性 `準確度 / reliability`
- `高 IQ` 或高適性官員的 comment：
  - 準確度較高
  - 較少出現偏題或誤判
- `普通 IQ` 或低適性官員的 comment：
  - 準確度較一般
  - 可能只反映部分現象，未能指出真正核心問題
- v1 不必在 UI 直接顯示數值化可靠度
- 但系統內部應保留這種設計空間，避免所有 comment 看起來完全等值
- 補充：
  - `suggestion priority` 與 `confidence / stance` 也應受這種隱性可靠度影響
  - 同一局勢下，高能力官員不只比較準，也更能表現出明確、可信的判斷

## 6. AI 規則

### 6.1 AI 是否需要任命

  - 同分時比較 `Loyalty`
- 首席軍師：
  - 優先 `Intelligence + Leadership + Charm`
  - 同分時比較 `Loyalty`

  - 可依城市需求在 `Politics / Intelligence / Leadership / Loyalty` 之間調整權重
  - 若該城偏前線，可提高 `Leadership`
  - 若該城偏內地發展，可提高 `Politics`

### 6.3 AI 重任命頻率
- `v1 建議`：
  - 缺位時才任命
  - 非缺位時不頻繁重洗

## 9. 與既有系統互動

### 9.1 君主死亡 / 繼承
- 新君主繼位後：
  - 若原中央職位持有人就是新君主，該職位清空
- 是否自動補任新職位：
  - `v1 建議`：不自動補任，由玩家或 AI 之後再任命

### 9.1.1 中央 comment 與長時程戰事
- 中央職位是否存在，與是否能在該月提供 comment，需分開看待
- 武將即使仍持有 `丞相` 或 `首席軍師` 頭銜，只要仍在戰場 / 出征流程 / 長時程戰事中，就可暫時不作為該月 comment 來源
- 此規則是為了避免 battle 跨月時，中央 comment 與實際人物狀態脫節

### 9.2 火除 / 登用 / 暗殺
- 被移除或轉移勢力時，自動清空中央職位

### 9.2A 太守與城市控制
- 若城市易主：
  - 原太守職位應清空
  - 新勢力需重新任命
- 若武將離城或不再符合該城太守資格：
  - 應先嘗試從同城武將中自動補任新太守
  - 只有在該城沒有可補任人選時，才進入空缺狀態
- 自動補任後：
  - 原城市的授權狀態應延續
  - 月計畫可依新任太守 characteristic 與當前局勢重新計算
  - 不需 player 再次手動授權
- `v1 實作修正`：
  - 若 Player 主動解除太守，城市授權狀態不延續，需立即清為 `None`
  - 若城市易主，授權狀態同樣不延續，需由新勢力重新決定
  - 若太守只是離城、被解雇、被挖角、陣亡或在攻城後失去原城資格：
	- 系統會先嘗試自動補任同城新太守
	- 若自動補任成功：
	  - `Full` 授權可依新太守重新生成自治計畫
	  - `Half` 授權保留玩家指定的計畫資料，但會中止舊 schedule，待新太守重新派工
	- 若無可補任人選：
	  - 城市授權會清為 `None`

### 9.3 Fog of War
- `v1 建議`：
  - 玩家只看見自己勢力的中央職位
  - 他方中央職位日後可透過情報系統解鎖

## 12. Role 與職位語意更新

### 12.1 基本原則

自本節起，Phase 2 文件統一使用以下定義：

- `Officer Role`
  - 代表武將的基礎身份
  - 來源為 JSON 初始資料
  - 目前基礎例子：
	- `Lord`
	- `General`
	- `Advisor`
- `職位 / Appointments`
  - 代表玩家或 AI 後天任命的職位
  - 同一名武將可同時持有多個職位
  - 不應再用 `Officer.Role` 承載全部任命資訊

### 12.2 目前規劃的職位

目前先納入職位系統的有：

- `丞相 / Chancellor`
- `軍師 / Strategist Post`
- `首席軍師 / Chief Strategist`
- `太守 / Governor / Prefect`

之後若新增其他中央或地方職位，也應視為同一套 `Appointments` 系統的擴充，而不是再擴大 `Officer.Role` 的語意。

### 12.3 可同時兼任

設計確認：

- 同一名武將可同時擁有多個 `職位`
- `Role` 與 `職位` 可同時並存

例：

- 關羽
  - `Role = General`
  - `Appointments = [太守, 丞相, 首席軍師]`

### 12.4 UI 顯示規則

之後所有查看與選將 UI，應優先分開顯示：

- `身份 / Role`
- `職位 / Appointments`

不要再把兩者混成單一「官職」欄位，否則玩家無法清楚分辨：

- 武將本身的基礎身份
- 後天被授予的中央 / 地方職位
- 是否正在兼任多個職位

### 12.5 資料模型方向

後續重構方向應為：

- `OfficerData.Role`
  - 保留基礎身份語意
- `Appointments`
  - 獨立保存武將現任職位
  - 支援多重任命
- faction-level / city-level 唯一職位限制
  - 應由職位系統規則處理
  - 不應再透過覆寫 `Officer.Role` 表達

### 12.6 過渡期說明

目前 codebase 仍有部分舊語意尚未完全拆開，例如某些地方仍把 `太守 / Governor` 視為 `Officer.Role` 的一種。

這屬於過渡實作，不代表最終資料語意。

文件自本節起，以「`Role = 基礎身份`、`職位 = 可多重任命`」作為後續設計準則。
