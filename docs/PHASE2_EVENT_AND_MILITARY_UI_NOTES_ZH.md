# Phase 2 事件演出與軍事 UI 實作備註

更新日期：2026-05-30

## 範圍

- 本文件補充 Phase 2 目前已落地的：
  - 月事件演出流程
  - 地圖事件標記規則
  - 軍事選將 UI 互動與視覺表現
  - `View` 表格與城市資訊面板的目前 UI 行為
- 內容以目前程式行為為準，供後續設計、UI 微調與 playtest 對照。

## 1. 月事件演出

### 1.1 事件資料來源

- 月事件演出資料來自：
  - `data/events/events.json`
- 目前每個事件定義可包含：
  - `eventType`
  - `picture`
  - `sound`
  - `durationSeconds`
  - `mapMarkerColor`

### 1.2 演出內容

- 當月底經濟與月事件結算完成後：
  - 事件會進入 presentation queue
  - 依序顯示事件圖片
  - 播放對應事件音效
  - 顯示事件 caption
- 多個事件不會同時播放，而是逐個排隊顯示。

### 1.3 同類事件合併播放

- 同一個月份內，若多座城市發生相同 `eventType`：
  - 事件演出只播放一次
  - 不重複顯示相同事件圖片與音效
- caption 會列出所有受影響城市
  - 例如：
    - `北海、洛陽 發生 地震`
- 合併規則只影響事件演出 queue
- 地圖上的城市事件標記仍然逐城保留，不會因為合併播放而只剩一座城顯示

### 1.4 圖片與音效

- 事件圖片來源：
  - `assets/event/`
- 事件音效來源：
  - `assets/sfx/events/`
- 若圖片缺失：
  - 仍保留 log 與地圖事件標記
- 若音效缺失：
  - 不阻斷事件播放流程

### 1.5 事件播放期間的 UI 可見性

- `End Turn` 後進入事件演出期間，會暫時隱藏非必要 UI
- 目前會暫時隱藏的內容包含：
  - 一般指令 / 功能 overlay dialogs
  - `城市資訊` 面板
- 目前保留可見的內容包含：
  - `top bar`
  - `log`
- 事件 overlay 會主動提到更高層級，顯示在 `top bar / log` 之上
- 當整段事件演出全部結束後：
  - 原本已開啟的 dialogs 會恢復顯示
  - `城市資訊` 面板也會恢復
  - 恢復時應盡量保留原本的視窗狀態與內容

## 2. 地圖事件標記

### 2.1 掛標時機

- `v1 實作`：
  - 月底事件一完成結算，就立即為所有受影響城市掛上事件標記
  - 不再等待事件圖片播放到該城市時才出現

### 2.2 保留時間

- 事件標記會保留整個月
- 到下一次月事件結算前，標記不會自動消失
- 下一輪月事件開始整理時，先清除上一輪月事件標記

### 2.3 視覺表現

- 城市圈圈外側會顯示事件脈動外環
- 目前為雙層效果：
  - 外層 glow
  - 內層較實的 pulse ring
- 城市名稱旁會顯示事件 tag
  - 繁中格式：`【事件名】`
  - 英文格式：`[Event]`
- 事件 tag 目前已加入深色陰影，降低底圖干擾

### 2.4 顏色區分

- 各事件使用 `events.json` 中的 `mapMarkerColor`
- `v1 調整`：
  - `plague` 改為較明顯的紫色系
  - `earthquake` 改為較明顯的亮橙系
- 原因：
  - 舊版 `plague / earthquake` 顏色在地圖底圖上不夠跳出

### 2.5 同城多事件

- 目前規則下，同一城市同一月份不會同時出現多個月事件
- 因此地圖標記目前只需要表示單一主事件

## 3. 軍事選將 UI

### 3.1 適用視窗

- 本節適用於：
  - `Attack`
  - `Move`

### 3.2 選取互動

- officer list 採用多選概念
- 第一欄顯示：
  - 未選：`○`
  - 已選：`●`
- 點擊 officer row 可切換選取狀態
- 已選 officer 會被納入後續出征 / 移動流程

### 3.3 視覺狀態

- 已選 row 會套用柔和高亮
- 高亮設計目標：
  - 可清楚辨識已選狀態
  - 但不要過亮、過銳利
- `v1 調整`：
  - 已選列改為較低飽和的霧金棕
  - 第一欄 `●` 亮度同步收斂

### 3.4 攻擊視窗中的配兵區

- `Attack` 視窗下半部會依已選 officer 動態生成配兵列
- 每列目前包含：
  - officer 名稱
  - troop type dropdown
  - troop count spinbox
- 若 troop type 為 `攻城兵 / Siege`，另外顯示：
  - 攻城器 dropdown
- 這些動態生成控制項應套用與 overlay 一致的 input theme

### 3.4A 攻城器指派規則

- 目前可指派的攻城器：
  - `衝車`
  - `投石車`
  - `雲梯`
- 只有當武將配置為 `攻城兵 / Siege` 時，才可指定攻城器
- 若切回非 `Siege` 兵種：
  - 攻城器選擇會自動清空
- 每位武將目前最多可指定 `1 種` 攻城器
- `Attack` 視窗下方摘要目前會同時顯示：
  - 各兵種已指派 / 可用數量
  - 各攻城器已指派 / 可用數量

### 3.4B 移動視窗中的攻城器

- `Move` 視窗目前已新增：
  - `衝車`
  - `投石車`
  - `雲梯`
  三個數量欄位
- 攻城器與：
  - 兵
  - 金
  - 糧
  - 馬
  - 武將
  一樣可隨 `Move` 命令在月底一起轉移

### 3.4C 奪城後的攻城器接管

- 目前奪城成功時：
  - 守方原城的攻城器庫存不保留
  - 只保留攻方本次 `Attack` 實際攜帶進城的攻城器
- 因此奪城後看到的新城攻城器數量，應是：
  - 攻方帶入數量
  - 不是守方舊庫存

### 3.5 徵兵 UI

- `Recruit` 目前已改為 `先選兵種 -> 再選數量 -> 再確認武將 / 成本` 的流程
- 視窗會先依城市條件過濾兵種：
  - `弩兵` 需 `弓坊`
  - `攻城兵 / Siege` 需 `工坊`
  - `騎兵` 需城市持有馬匹
- 選定兵種後，UI 會即時計算並顯示：
  - 可徵募上限
  - `Gold`
  - `Food`
  - 若為 `騎兵`，另外顯示 `Horse`
- 可徵募上限目前依下列條件共同限制：
  - 城市 `Gold`
  - 城市 `Food`
  - 城市 `Population`
  - 特殊條件資源，例如 `Horse`
- 玩家輸入的數量不可超過目前上限
- 視窗內顯示的成本為實際本次命令成本，而非固定票價

## 4. `View` 與城市資訊 UI

### 4.1 城市設施顯示

- 左側 `城市資訊` 面板目前顯示：
  - `弓坊`
  - `工坊`
  - `馬場`
- 顯示格式為：
  - `等級(目前進度/下級門檻)`
- 範例：
  - `0 (40/100)`
- `View Cities` 目前也顯示同樣格式，方便跨城比較

### 4.1A 攻城器顯示

- `View Cities` 目前另外顯示：
  - `衝車`
  - `投石車`
  - `雲梯`
- 顯示格式為：
  - `數量(目前進度/下一件門檻)`
- 範例：
  - `1 (20/100)`

### 4.2 建設點語意

- `建設 / Construction` 不再是單次完工直接 `level +1`
- 目前為 `建設點 / Construction Points` 累積制
- 每月底把：
  - `每月投入金`
  - 武將能力
  - 建設職系加成
- 轉為建設點，再累積到對應設施

### 4.2A 攻城器建造語意

- 當城市已具備 `工坊 / SiegeWorkshop` 後
- `Construction` 目前可選：
  - `衝車`
  - `投石車`
  - `雲梯`
- 攻城器目前也走建設點累積制
- 每件產出門檻為：
  - `100 建設點`
- `內政` 排程列表會顯示該建設案目前進度
  - 例如：
    - `建設 (投石車 1 (20/100))`

### 4.2B AI 攻城器建造

- AI 目前已可建造：
  - `衝車`
  - `投石車`
  - `雲梯`
- 但仍先以補齊基礎設施為前提
- 基礎設施齊後：
  - 前線城偏向攻城器
  - 後方城偏向基礎設施

### 4.3 `View` 表格現況

- `View` 目前仍使用 Godot `Tree`
- row zebra 背景目前由程式逐 cell 套用：
  - `SetCustomBgColor(...)`
- 已知現況：
  - 某些表格在初次顯示時，row 背景與欄位實際寬度的繪製時機可能不同步
  - 點擊 row 後通常會觸發正確重繪
  - 單純捲動不一定會立即重刷整列背景
- 因此目前 `View` 表格的 row fill 屬於：
  - 已有基線版可用
  - 但仍需後續針對 Godot `Tree` redraw 行為再觀察與微調
- 這屬於 UI 呈現層已知問題，不影響資料本身與排序 / 點擊功能正確性

### 4.4 `View` dialog 與地圖選城同步

- `View` dialog 開啟期間，玩家若直接在地圖點選其他城市：
  - 左側 `城市資訊` 會刷新
  - `View` dialog 目前也會同步刷新
- 刷新內容包含：
  - dialog title / chrome
  - `本城武將`
  - `全勢力武將`
  - `城市`
  - `勢力道具`
  - `外交關係`
- 目的是讓 `View` dialog 永遠跟隨目前 `_selectedCity`
  - 不需要先關閉 dialog 再重開

### 4.5 語言切換與動態 UI

- 目前多數 overlay dialog 在語言切換時，不只更新靜態 label / button，也會同步重建動態 UI 文字。
- 目前已支援即時語言切換的動態控制項包含：
  - `OptionButton / dropdown`
  - `Officer Selector` table columns / rows / title / confirm button
  - `Attack` 視窗中的：
    - target city dropdown
    - officer table header / row text
    - deployment editor 動態建立的 troop type / siege engine dropdown
- 目前實作原則：
  - 開著 dialog 切語言時，不要求玩家先關閉視窗再重開
  - 若控制項有使用者當前狀態，應盡量保留：
    - 已選項目
    - 已勾選 officer
    - 已建立 deployment 狀態
    - 已輸入數值
- `Officer Selector` 目前已補：
  - title 可隨語言即時更新
  - 自訂欄位配置可重建
  - scope buttons 可隨語言更新
  - row text 會以目前語系重算
- 這代表像：
  - `內政 -> 指派武將`
  - `外交 -> 選使者`
  - `間諜 -> 選執行武將`
  - `人事 -> 指派官職 / 招攬 / 沒收寶物`
  這類共用 officer selector 的流程，現在開著 selector 也可直接切換語言。

## 5. 啟動畫面與君主選擇 UI

### 5.1 啟動流程

- 啟動時目前先進入 `Main Menu`
- `Main Menu` 提供：
  - `Start Game`
  - `Load Game`
- `Start Game` 進一步進入：
  - `Select Story`
  - `Select Lord`
  - 再進入 `Game Mode`
- `Load Game` 會開啟 load UI，讀取完成後直接進入 `Game Mode`

### 5.2 君主選擇畫面

- `Select Lord` 目前顯示：
  - 可扮演勢力列表
  - 劇本名稱
  - 所選勢力摘要
  - 君主人像
- 人像來源沿用既有 portrait atlas 與 mapping
- 若找不到對應 `charId` 的 portrait mapping：
  - UI 退回 placeholder
  - 不阻塞選主流程

### 5.3 Portrait mapping 語意

- `person_image_*.json` 中的：
  - `x`
  - `y`
  - `width`
  - `height`
  是 atlas 裁切框
- 不是 UI 顯示尺寸或縮放比例
- 因此若修改 `width / height`：
  - 會造成裁切範圍改變
  - 可能讓 portrait 看起來被 crop

### 5.4 死亡年份與劇本登場

- 劇本初始化時，目前人物登場規則為：
  - 死亡年份當年仍可登場
  - 下一年起才排除
- 這是為了避免如 `184 年黃巾之亂` 劇本中：
  - `張角 death_year = 184`
  - 卻在開局即被過濾掉
- 這個規則已同步到：
  - scenario 初始載入
  - alive helper
  - free officer 可見性
  - spy target officer 篩選
