# 俘虜系統回歸驗證 Checklist

更新日期：2026-06-06

## 1. 目的

- 固定化 `俘虜系統` 的手動回歸驗證流程。
- 避免後續調整戰鬥、移動、View UI、log 或 localization 時，破壞既有俘虜功能。

## 2. 驗證範圍

- 戰後俘虜處置 dialog
- `Personnel -> 管理俘虜`
- `Move` 轉移俘虜
- `View officer dialog` 的俘虜顯示
- 每月俘虜脫逃與 log
- 關押城市失守時的俘虜釋放
- 開著 dialog 切語言的即時刷新

## 3. 前置條件

- 使用可進入戰鬥與月底結算的存檔或測試局。
- 至少準備一名可被俘的敵方武將。
- 至少準備兩座同勢力城市，供 `Move` 測試轉移俘虜。
- 若要驗證脫逃，建議準備：
  - 低城防城市
  - 低民忠城市
  - 至少一名已下獄俘虜

## 4. 回歸案例

### Case 1: 戰後俘虜處置

- 步驟：
  1. 進行一場會產生俘虜的戰鬥。
  2. 若同月底有多場攻擊，讓所有 attack 結算完整跑完。
  3. 確認進入下月後才跳出俘虜處置 dialog，而不是戰鬥鏈中途。
  3. 依序驗證 `招降 / 釋放 / 處決 / 下獄` 四種選項。
- 預期：
  - 玩家勝方會在「全部戰鬥結束、進入下月月頭後」看到處置 dialog。
  - 俘虜處置不應插入 attack resolution 中途。
  - 每個選項都可正常完成，不出現卡死或 null / index error。
  - `下獄` 後，武將進入俘虜狀態，而非留在原勢力正常武將名單。
  - 若 `招降` 被拒絕，應停留在俘虜狀態，且玩家仍可改選其他處置。

### Case 2: 管理俘虜視窗

- 步驟：
  1. 選到關押俘虜的城市。
  2. 開啟 `Personnel -> 管理俘虜`。
  3. 分別測試：
     - 不加碼直接 `招降`
     - 帶 `金 / 寶物 / 官職` 的 `招降`
     - `釋放 / 處決`
- 預期：
  - 僅列出目前選中城市在押的俘虜。
  - 執行動作後，列表、摘要與實際資料同步更新。
  - 沒有俘虜時，應顯示空狀態文案，而不是殘留上一位俘虜資料。
  - `招降` 失敗時，俘虜不可憑空消失，也不可誤加入我方武將名單。
  - 帶加碼條件時，只有招降成功才會真正扣金、發寶物、套用官職。

### Case 3: Move 轉移俘虜

- 步驟：
  1. 在有俘虜的城市開啟 `Move`。
  2. 選擇至少一名一般武將與至少一名俘虜。
  3. 指定目標城市並結束回合。
- 預期：
  - `Move` 視窗可勾選同城俘虜。
  - 月底後，俘虜應改為關押在目標城市。
  - 俘虜不應變成一般可任命武將。
  - 結算 log / summary 應帶出俘虜轉移資訊。

### Case 4: View Officer Dialog 顯示

- 步驟：
  1. 開啟 `View officer dialog` 的 `本城武將`。
  2. 再查看 `全勢力武將`。
  3. 分別檢查包含俘虜與非俘虜的列。
- 預期：
  - 俘虜直接併入 officer list，不另開獨立頁籤。
  - `官職` 欄顯示為 `俘虜`。
  - `本城武將` 只顯示目前關押於該城的俘虜。
  - `全勢力武將` 的 `城市` 欄顯示關押城市，而不是空白或原任職城市。
  - 同一名俘虜不應重複出現在列表中。

### Case 5: 每月脫逃與 log

- 步驟：
  1. 在低城防或低民忠城市保留至少一名俘虜。
  2. 連續結束多個月，觀察月底結果。
- 預期：
  - 俘虜有機會脫逃，不需玩家額外操作。
  - 脫逃後，該武將不再留在關押城市俘虜列表。
  - log 會寫入俘虜脫逃訊息。
  - 未脫逃時，不應產生錯誤 log 或異常狀態。

### Case 6: 關押城市失守

- 步驟：
  1. 將俘虜關押在前線城市。
  2. 讓該城市被敵方攻下。
  3. 檢查失守後俘虜資料與 View 顯示。
- 預期：
  - 原本關押於該城的俘虜會脫離拘禁。
  - 俘虜不再出現在舊勢力的俘虜清單。
  - 不應殘留無效的 `JailedCity` / captive 顯示。

### Case 7: Live Localization

- 步驟：
  1. 分別開啟 `Captured Officer` dialog、`管理俘虜`、`Move`、`View officer dialog`。
  2. 在視窗開啟中切換語言。
- 預期：
  - 標題、按鈕、欄位標頭、動態列內容會即時刷新。
  - 已選中的俘虜、已勾選項目、已輸入值應被保留。
  - 不應因 refresh 造成 selection 遺失或索引錯誤。

### Case 8: AI 最低相容驗證

- 步驟：
  1. 讓 AI 勝出一場可能產生俘虜的戰鬥。
  2. 觀察戰後是否可正常結束流程並繼續遊戲。
- 預期：
  - AI 可處理戰後即時俘虜結果，不會卡在 unresolved state。
  - 至少不應造成 turn flow 中斷、例外或 battle result 卡住。
- 備註：
  - 目前此案例只驗證 AI 對「戰後立即處置」的最低相容性。
  - 不代表 AI 已完整具備長期俘虜經營策略。

## 5. 驗收標準

- 上述 8 個案例全部可重現且符合預期。
- 驗證期間不得出現：
  - UI 卡死
  - `Index out of bounds`
  - 俘虜重複顯示
  - 俘虜誤轉為一般武將
  - 關押城市 / 所屬勢力資料殘留錯誤
